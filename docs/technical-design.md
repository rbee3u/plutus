# Technical Design

Status: describes the code on `dev` after Phase 4 (restructure to the accepted model). Everything in this document is implemented unless a paragraph is marked **Phase 5**, which covers the live Binance, OKX, and Bybit Adapters that still replace the deterministic `fake` Adapter.

This document turns the [glossary](../CONTEXT.md) and the accepted [ADRs](./adr/) into a contract for the backend and frontend. The reasons for the model are recorded in ADRs [0014](./adr/0014-store-one-valuation-point-per-collection-cycle.md) through [0021](./adr/0021-report-each-account-with-one-aligned-account-report.md).

## 1. Goals and boundaries

Plutus answers two questions for one User's Portfolio, in this order of importance:

1. **How much is there now, and where.** A Platform → Identity → Account tree with each Account's report, Balances, and Positions, and a USD total per Account, per Platform, and for the Portfolio. This view must match what the owner sees in each exchange app.
2. **How did the total change over a period, excluding my own transfers.** A Valuation Point series, Period Closes, and Value Change by calendar day, ISO week, month, quarter, and year, with manual Capital Flows and Boundary Events subtracted.

Deliberately outside the product:

- percentage returns, return attribution, per-trade or per-strategy analysis, a transaction ledger;
- trading, transfers, or any Platform write operation, and any Platform call that needs more than read-only balance, position, and market-data permission ([ADR 0020](./adr/0020-record-capital-flows-manually-with-read-only-credentials.md));
- automatic deposit/withdrawal import or internal-transfer matching;
- storage of raw Platform response payloads;
- currencies other than USD, and observed stablecoin or fiat exchange rates ([ADR 0017](./adr/0017-value-in-usd-and-treat-major-stablecoins-as-usd.md));
- Exposure aggregation by underlying Asset ([ADR 0021](./adr/0021-report-each-account-with-one-aligned-account-report.md));
- sub-account collection through a main-account credential ([ADR 0015](./adr/0015-select-account-types-per-identity.md));
- shared Portfolios, roles, email, OAuth, password recovery, multi-instance HA, PWA, native apps, Prometheus, OpenTelemetry;
- manually tracked non-exchange assets (a later product release).

Platform and Account Mode scope remains [ADR 0005](./adr/0005-support-explicitly-selected-unified-account-modes.md): Binance Portfolio Margin, OKX Multi-currency margin and Portfolio margin, Bybit Unified Trading Account 2.0. The Account Types each mode offers are declared in code (`internal/adapters`):

| Account Mode | Account Types |
| --- | --- |
| `binance_pm` | `portfolio_margin`, `spot`, `funding`, `earn` |
| `okx_mcm`, `okx_pm` | `trading`, `funding`, `earn` |
| `bybit_uta_2_0` | `unified`, `funding`, `earn` |

## 3. Runtime architecture

### 3.1 Deployment unit

One Go process and one externally managed MySQL server. The process serves the JSON API, runs the scheduler and job worker, and serves the embedded React build. Plutus does not start, stop, back up, or upgrade MySQL.

```text
Browser
  | HTTPS or HTTP; JSON under /api/v1
  v
Go process (plutus serve)
  +-- HTTP transport (Gin, generated strict interface)
  +-- application services (one package per aggregate)
  +-- sqlc queries --------------------------------> MySQL 8.4
  +-- scheduler: one Collection Cycle per Portfolio -^
  +-- job worker: runs cycles and recalculations, writes Valuation Points
  +-- Platform adapters ---------------------------> external Platforms (Phase 5) / fake
  +-- embedded React SPA
```

Only one Plutus process may be active for a database. Job leases give restart recovery, not multi-instance coordination.

### 3.2 Modules and dependency direction

A modular monolith under `internal/`. Each service package owns one aggregate and its sqlc queries; it calls other aggregates only through their exported service methods. The transport layer never imports sqlc output, and no service package imports Gin or the generated OpenAPI types.

```text
cmd/plutus (composition root, CLI)
    |
    v
transport/http (Gin, generated api, Problem Details, ETags, idempotency)     worker (leases, scheduler)
    |                                                                           |
    v                                                                           v
auth  portfolio  identity  catalog  capital  valuation  jobs  <----------  collection
    \        |        |        |        |        |        |                  |
     \-------+--------+--------+--------+--------+--------+------------------+
                                     |
                                     v
                 infra/mysql (Open, Up, sqlcgen, sqljson)   secret (AES-GCM)   adapters (port, fake)
```

| Package | Owns |
| --- | --- |
| `auth` | Users, Argon2id password hashes, Sessions, CSRF secrets, login throttling |
| `portfolio` | Portfolios, the collection interval, the undeletable birth Portfolio, cascade delete |
| `identity` | Identities, the Connection embedded in each Identity (credentials, status, last outcome), Accounts and their selection |
| `catalog` | Asset Listings (symbol mapping), Instruments, Platform prices |
| `collection` | one Collection Cycle: adapter calls with retry, Account Reports, Balances, Positions, prices, then the Valuation Point |
| `valuation` | Account Valuation and Valuation Point writing and rebuilding; Overview, tree, flat lists, series, Period Closes, Value Changes, Boundary Events |
| `capital` | manual Capital Flows and their USD valuation |
| `jobs` | durable jobs: enqueue with deduplication, `SKIP LOCKED` claims, leases, retry, pruning, cycle listing |
| `worker` | the loop that claims jobs, runs handlers, schedules cycles, and prunes finished jobs |
| `adapters` | the read-only Platform port, the Platform/Account Mode/Account Type catalog, error classes, the `fake` Adapter |
| `audit`, `idempotency`, `secret`, `decimal`, `config`, `infra/mysql` | cross-cutting support |

Removed by Phase 4: `access`, `observation`, `projection`, generation switching, correction endpoints, coverage logic, Exposure, catalog pins, Capital Baselines, and every revision table.

### 3.3 Collection Cycle flow

```text
scheduler tick (every 15 s): for each Portfolio with an enabled Connection
  whose last cycle job was created >= collection_interval ago
      -> jobs.EnqueueCycle(schedule)            dedupe: one active cycle per Portfolio
POST /collection-cycles                          -> jobs.EnqueueCycle(manual), same dedupe
worker claims the job (FOR UPDATE SKIP LOCKED lease, renewed every lease/3)
collection.RunCycle(portfolio, job):
  boundary    = selected Accounts of enabled Identities
  collectable = enabled Identities whose Connection is enabled, credentials decrypted
  for each collectable Identity, staggered by [collection].stagger:
      adapter.Collect(credentials, mode, selected Account Types)   retried after 2 s and 5 s
                                                                    on rate_limited / temporary
      failure  -> one failed account_reports row per Account with the error class;
                  authentication / authorization also sets the Connection invalid
      success  -> in one transaction: prices, one ok report per Account with its
                  balances and positions (listings and instruments upserted on sight),
                  failed reports for Accounts the adapter reported as failed or omitted
  boundary Accounts without a report (Connection disabled, invalid, unconfigured)
      -> failed report with class `skipped`
  valuation.WritePoint(portfolio, job, now)
      -> values every report of the job, writes the value columns on account_reports,
         derives Boundary Events against the previous point, upserts one valuation_points row
job succeeded with a summary; a runner error retries with backoff up to 3 attempts, then failed
```

The reports written for a job define the Portfolio Boundary at that point: one row per selected Account, `ok` or `failed`. A cycle never rewrites earlier reports. A wholly failed cycle still writes a Valuation Point built from stale reports, so the series has no gaps while the process is alive; a day on which the process was down has no points and therefore no Period Close.

### 3.4 Valuation rules

For each Account Report of the job:

| Report | Source report | Freshness | Method |
| --- | --- | --- | --- |
| `ok` | itself | `fresh` | `reported` when `equity` is present, else `calculated` |
| `failed`, an earlier `ok` report exists | the latest earlier `ok` report of the Account | `stale` | as above, from the source report |
| `failed`, never succeeded | none | `stale` | `missing`, `value_usd = NULL` |

`calculated` is Σ `balances.equity × price` over the source report's Balances. USD, USDT, and USDC are 1 ([ADR 0017](./adr/0017-value-in-usd-and-treat-major-stablecoins-as-usd.md)). Any other Asset uses the same Platform's latest price at or before the report's observation time, or, failing that, the nearest price on any Platform, provided the price is quoted in USD/USDT/USDC and at most 24 hours old. A Balance with no such price is listed in `omitted_json` with reason `no_price` and excluded from the value; the Account and the point are then `incomplete`. Zero-equity Balances are ignored.

The Valuation Point total is the sum of every non-null `value_usd`. `stale_account_count` counts stale Accounts with a value; `incomplete_account_count` counts `missing` Accounts and Accounts with omitted Balances. Issues (`missing`, `stale`, `no_price`, `boundary_unvalued`) are stored on the point and returned with every read.

Boundary Events are derived when the point is written by comparing its Account set with the previous point: an Account that appears is a contribution equal to its `value_usd`; an Account that disappears is a withdrawal equal to its last `value_usd` ([ADR 0016](./adr/0016-treat-boundary-events-as-implicit-capital-flows.md)). Unvalued Accounts produce a `boundary_unvalued` issue instead of an amount. Events are stored in `boundary_json` with their USD totals in `boundary_contribution_usd` and `boundary_withdrawal_usd`.

`valuation.Rebuild` recomputes every succeeded cycle's point in order, keeping each `evaluated_at`; it runs after a mapping override (as a `valuation_recalc` job) and after seeding.

### 3.5 Adapter boundary

```go
type Adapter interface {
    // Capabilities lists the Account Types this adapter can collect per Account Mode.
    Capabilities() map[AccountMode][]AccountType
    // Validate performs one read-only call and returns the Platform's own identity ref.
    Validate(ctx context.Context, creds Credentials, mode AccountMode) (ValidationResult, error)
    // Collect returns one AccountReport per requested Account Type, with balances,
    // positions, and the prices needed to value them.
    Collect(ctx context.Context, creds Credentials, mode AccountMode, accounts []AccountType) (Batch, error)
}
```

`Batch` carries only normalized values, Platform observation times, and structured per-Account failures. Errors are classified as `authentication`, `authorization`, `rate_limited`, `temporary`, `unsupported`, or `normalization`; the first two stop scheduling (Connection `invalid`), the next two are retried within the cycle. Raw payload bytes never cross this boundary, are never logged, and are never persisted. An Adapter maps every Platform field into the fixed columns of §5.5; unsupported measures are null.

The `fake` Adapter is deterministic: values derive from the API key and the time, so seeded history and live cycles form one continuous series. Key prefixes select behavior: `invalid-` (authentication), `forbidden-` (authorization), `ratelimit-` (rate limited), `flaky-` (one temporary error per minute, then success), `empty-` (empty reports), `unpriced-` (adds a `TOKENX` Balance that has no price); anything else succeeds. **Phase 5** registers real Adapters per Platform behind the same port.

## 4. Cross-cutting data rules

### 4.1 Database settings and identifiers

- InnoDB, `utf8mb4`, MySQL strict mode required; the process refuses readiness when migrations are pending and never migrates automatically.
- Entity identifiers are application-generated UUIDv7 stored as `BINARY(16)`; the API uses lower-case canonical UUID strings.
- Status and kind fields are `VARCHAR` plus `CHECK`, not MySQL `ENUM`.
- Foreign keys use `RESTRICT`. Deleting an additional Portfolio removes every row scoped to it in one transaction, in dependency order.
- Every Portfolio-scoped table has `portfolio_id`, `UNIQUE (portfolio_id, id)`, and composite foreign keys such as `(portfolio_id, identity_id) -> identities (portfolio_id, id)`.
- Every scoped read resolves the Portfolio through the Session's User first. A missing Portfolio and another User's Portfolio both return HTTP 404.

### 4.2 Decimal and JSON representation

All quantities, prices, and values are `DECIMAL(65,30)`; application arithmetic is exact rational arithmetic with formatting only at the storage and JSON boundary. No `float64` reaches a financial column. JSON represents every financial decimal as a string, including `"0"`. `null` means unknown or not applicable, never zero. The frontend uses `decimal.js`; only chart adapters convert to JavaScript numbers.

### 4.3 Time and timezone

MySQL session timezone is UTC. Time points are UTC `DATETIME(6)` serialized as RFC 3339. Each Portfolio stores an IANA timezone (default `Asia/Shanghai`) used to compute Period Close boundaries, `day`/`hour` sampling buckets, and Value Change periods at query time; changing it changes what future queries return and requires no recalculation because Valuation Points are timezone-free.

### 4.4 Versioning and retention

Configuration rows (`portfolios`, `identities`, `accounts`, `asset_listings`, `capital_flows`) carry an integer `version` for ETags. Account Reports, Balances, Positions, prices, Valuation Points, and audit events are append-only and kept indefinitely. Finished jobs that produced no report or point (recalculations, failed cycles without reports) are pruned after `[jobs].completed_retention`; cycle jobs that own reports are kept with them. There is no retention or downsampling for Valuation Points in this release ([ADR 0014](./adr/0014-store-one-valuation-point-per-collection-cycle.md)).

## 5. MySQL schema catalog

Normative logical schema, implemented by the single baseline migration `db/migrations/20260922120000_schema.sql`. Sixteen tables. The previous schema was dropped, not migrated.

Conventions: `_id` fields are `BINARY(16)` and required unless marked nullable; `_at` fields are UTC `DATETIME(6)`; codes and states are `VARCHAR` with a `CHECK`; safe human-readable details are `VARCHAR(1024)`; financial values are `DECIMAL(65,30)`; versions are `BIGINT UNSIGNED`. `created_at` and `updated_at` are present on every configuration table and omitted below.

### 5.0 Why sixteen tables

Each merge below removes a table that would have had exactly one row per row of its parent, or that stored a fact already expressed elsewhere:

| Removed | Now | Reason |
| --- | --- | --- |
| `connections` | columns on `identities` | one Identity has exactly one Connection ([CONTEXT](../CONTEXT.md)); a separate row only added a join and a uniqueness rule |
| `platforms` | `CHECK` constraints plus the adapter registry | Platforms are code, not data; their Account Modes and Types are declared by Adapters |
| `assets` | `asset_symbol` on `asset_listings` | an Asset is its normalized symbol ([ADR 0018](./adr/0018-merge-asset-listings-by-symbol-with-manual-overrides.md)); a row per symbol carried no other fact |
| `collection_cycles`, `collection_runs` | the `collection_cycle` job plus `identities.last_collected_at` / `last_error_*` | the job already has trigger, timestamps, status, and attempts; a run's outcome is visible on the Identity and in its Account Reports |
| `account_valuations` | value columns on `account_reports` | one valuation per report per cycle; the report row is the natural home for `value_usd`, `method`, `source_report_id`, `omitted_json` |
| `valuation_issues`, derived Boundary Events | `issues_json`, `boundary_json` on `valuation_points` | read together with the point, never queried alone |
| `price_observations` | `prices` keyed by `(platform, asset_symbol, observed_at)` | one price type, one quote family (USD-equivalent); no surrogate key needed |
| `job_attempts`, `*_job_details` | `attempt_count`, `last_error_*`, `payload_json` on `jobs` | the last attempt is what operators act on; payloads are small |
| `identity_snapshots`, `observations` header, `reported_equity_observations`, coverage tables, `account_metric_observations` | `account_reports` | one aligned report per Account per cycle ([ADR 0021](./adr/0021-report-each-account-with-one-aligned-account-report.md)) |
| `capital_baselines`, every `*_revisions` table, `catalog_pins`, `projection_*` | removed | Capital Baselines, revisions, pins, and generations are out of the model |

### 5.6 Manual source facts

#### `capital_flows`

`id`, `portfolio_id`, `direction` contribution|withdrawal, `asset_symbol`, `quantity` > 0, nullable `value_usd`, `effective_at`, nullable `account_id` (composite FK), nullable `note`, `created_by_user_id`, `version`. `value_usd` is supplied by the User or derived from the nearest stored price at or before `effective_at` within 24 hours (USD/USDT/USDC at 1); a flow without a value makes every Value Change spanning it `incomplete` and is named in its reasons. Editable in place with ETag; every create, update, and delete writes an `audit_events` row.

## 6. JSON API contract

### 6.1 Conventions

OpenAPI 3.1 under `api/openapi/openapi.yaml` is the source of truth. Endpoints live below `/api/v1`; Portfolio resources include `{portfolioId}`; health endpoints are unversioned. JSON is `camelCase`, unknown request fields are rejected, decimals are strings, instants are RFC 3339.

List responses are typed: `items`, `page`, `context`, `issues`. Financial responses carry `completeness` (`complete` | `incomplete`) and, per Account, `freshness` (`fresh` | `stale`), `method`, and `reportObservedAt`. An incomplete or stale result is a 2xx response with real numbers and an issue list; only request validation, authentication, CSRF, ETag, idempotency, state, and infrastructure failures are non-2xx. Errors use `application/problem+json` with `code`, `traceId`, `instance`, and optional `fieldErrors`:

| Status | `code` | When |
| --- | --- | --- |
| 400 | `validation_failed` | malformed input, unknown field, invalid cursor or range |
| 401 | `unauthenticated` | missing or expired Session |
| 403 | `csrf_invalid` | state-changing request without a valid CSRF token |
| 404 | `not_found` | unknown or foreign Portfolio, resource, or point |
| 409 | `conflict`, `state_conflict`, `undeletable` | duplicate name or idempotency body; action not allowed in the current Connection state (archived, enabled, no credentials); deleting the birth Portfolio |
| 412 | `precondition_failed` | `If-Match` mismatch |
| 422 | (body: `ValidationOutcome`) | `POST .../enable` when the Platform rejected the credentials |
| 503 | `unavailable` | credential writes without a master key, or no Adapter for the Platform |

### 6.2 Authentication and Sessions

`GET /auth/csrf`, `POST /auth/login`, `POST /auth/logout`, `POST /auth/logout-all`, `GET /auth/me`, `PUT /auth/password`, `GET /auth/sessions`, `DELETE /auth/sessions/{sessionId}`. Cookie, CSRF, rate-limit, Argon2id, and Session lifetime rules are unchanged from Phase 1. Responses under `/auth`, `/identities`, and `/audit-events` are `Cache-Control: no-store`.

### 6.3 Portfolios and Platforms

`GET, POST /portfolios`; `GET, PATCH, DELETE /portfolios/{portfolioId}`. PATCH changes `name`, `timezone`, or `collectionIntervalSeconds`. `GET /platforms` lists the supported Platforms with their Account Modes and Account Types from the adapter catalog.

### 6.4 Identities and Connections (under `/portfolios/{portfolioId}`)

| Method and path | Purpose |
| --- | --- |
| `GET, POST /identities` | create with `platform`, `displayName`, `accountMode`, and the initial `selectedAccountTypes` (`Idempotency-Key`) |
| `GET, PATCH /identities/{identityId}` | rename; `accounts[]` patches toggle `selected` or rename an Account (`If-Match`) |
| `POST /identities/{identityId}/archive` | refused (409) while the Connection is enabled |
| `PUT /identities/{identityId}/credentials` | write-only `apiKey`, `apiSecret`, optional `passphrase`; the Connection becomes `disabled` |
| `DELETE /identities/{identityId}/credentials` | removes credentials; the Connection becomes `unconfigured` |
| `POST /identities/{identityId}/validate` | one bounded read-only call; stores `externalRef` or the error; an authentication or authorization error sets `invalid`, a success clears `invalid` to `disabled` |
| `POST /identities/{identityId}/enable` | validates first; on success the Connection is `enabled` (200), otherwise 422 with the `ValidationOutcome` and the unchanged or `invalid` Connection |
| `POST /identities/{identityId}/disable` | stops scheduling; requires stored credentials |

Every Identity response embeds `connection` (`status`, `credentialsConfigured`, timestamps, `lastErrorClass`, `lastErrorDetail`) and `accounts`.

### 6.5 Collection Cycles

`POST /collection-cycles` enqueues a manual cycle and returns 202 with the job, or the already active job. `GET /collection-cycles` lists cycle jobs newest first with each job's point summary (cursor pagination); `GET /collection-cycles/{cycleId}` returns the job, its point, and the per-Account outcomes.

### 6.6 Current-state endpoints

| Method and path | Purpose |
| --- | --- |
| `GET /overview` | latest point, totals per Platform and per Identity, stale and incomplete counts, issues, a 24-hour hourly sparkline |
| `GET /tree` | the Platform → Identity → Account tree at the latest point: each Account's report fields, `valueUsd`, `method`, `freshness`, `reportObservedAt`, `omitted` |
| `GET /accounts/{accountId}/balances` | Balances of the Account's source report with `valueUsd` per row and `noPrice` markers |
| `GET /accounts/{accountId}/positions` | Positions of the Account's source report with `notionalUsd` |
| `GET /balances` | flat Balance list across the boundary; filters `platform`, `identityId`, `accountId`, `symbol`; `groupBy` asset|platform|identity|account returns backend totals; offset pagination up to 500 rows |
| `GET /positions` | flat Position list with the same filters |

Clients never sum paginated rows; every total comes from the backend.

### 6.7 History endpoints

| Method and path | Purpose |
| --- | --- |
| `GET /valuation-points` | series between `from` and `to` (default: last 7 days); `granularity` raw|hour|day keeps the last point per local bucket |
| `GET /valuation-points/{pointId}` | one point with its Account Valuations and issues |
| `GET /period-closes` | Period Close per `periodKind` (day default; week, month, quarter, year) between two instants; a period without a point has `point: null` |
| `GET /value-changes` | Value Change per `periodKind` with `startPoint`, `endPoint`, `contributionsUsd`, `withdrawalsUsd`, `boundaryContributionsUsd`, `boundaryWithdrawalsUsd`, `amountUsd`, `completeness`, `reasons`, `boundaryEvents` |
| `GET /value-changes/custom?from=&to=` | one Value Change between the last points at or before two instants |
| `GET /boundary-events` | derived Boundary Events between two instants (default: last 90 days) |

Default windows when `from`/`to` are absent: 30 days for `day`, 26 weeks, 12 months, 12 quarters, 5 years, starting no earlier than the Portfolio's first Valuation Point (no point, no periods). Period boundaries use the Portfolio timezone; a Period Close is the last point strictly before the boundary. A week, month, quarter, or year containing a local day without any point is `incomplete` with reason `days_without_points`.

### 6.8 Capital endpoints

`GET, POST /capital-flows` (`from`/`to` filter, `Idempotency-Key`); `GET, PATCH, DELETE /capital-flows/{flowId}` (`If-Match`). A PATCH may send `accountId: null` or `valueUsd: null` explicitly to detach the Account or drop a manual value; absent fields are unchanged.

### 6.9 Catalog, jobs, audit

`GET /catalog/asset-listings` (`platform`, `q`, offset pagination) and `PUT /catalog/asset-listings/{listingId}/mapping` (`assetSymbol`, `If-Match`; enqueues recalculation for affected Portfolios); `GET /catalog/instruments`; `GET /jobs` (`kind` filter, cursor) and `GET /jobs/{jobId}`; `GET /audit-events` (cursor).

### 6.10 Concurrency, idempotency, pagination, health

Strong ETags (`"resource:version"`) with required `If-Match` on `PATCH`, `PUT`, `DELETE`, and Connection actions; `Idempotency-Key` on creates and the manual cycle trigger, replaying the stored response for an identical body and returning 409 for a different one; offset pagination for current-state and catalog lists, HMAC-signed cursor pagination for cycles, jobs, and audit; `GET /health/live` and `GET /health/ready` (MySQL reachable, schema version current, master key present when ciphertext exists, worker heartbeat fresh).

## 8. Security and configuration

Configuration is a non-secret TOML file (`--config`, default `config/local.toml`) plus an env file (`--env-file`, default `config/local.env`) holding `PLUTUS_DATABASE_DSN` (or `_FILE`) and `PLUTUS_MASTER_KEY` (or `_FILE`). Sections: `[server]` and `[server.tls]` (HTTP / HTTPS / mTLS startup matrix), `[auth]` (Session lifetimes, cookie names), `[jobs]` (`worker_poll_interval`, `lease_duration`, `completed_retention`), `[database]` (`allow_reset`), and:

```toml
[collection]
default_interval = "15m"      # Collection Cycle interval for new Portfolios; each Portfolio may override
stagger = "3s"                # delay between Identities within one cycle
validate_timeout = "15s"      # bound for one synchronous Connection validation
fake_adapter = true           # register the deterministic offline Adapter for every Platform
```

Credentials are sealed with AES-256-GCM under the 32-byte master key, with the Identity and Portfolio IDs and the key version as associated data; the key never appears in TOML. Credential writes, validation, and enabling return 503 `unavailable` without a master key; readiness fails when ciphertext exists and the key is absent. Browser security (Argon2id, HttpOnly session cookie, double-submit CSRF, login throttling, `no-store` on sensitive routes, body limits, allowed dev origins) is unchanged from Phase 1.

## 9. Scheduling and failure policy

- The scheduler ticks every 15 seconds and enqueues one `collection_cycle` job per Portfolio that has at least one enabled Connection and whose newest cycle job was created at least `collection_interval_seconds` ago. Manual triggers use the same job and dedupe key, so at most one cycle is active per Portfolio.
- Within a cycle, Identities are collected sequentially with the configured stagger. Connections that are not `enabled` are skipped; their selected Accounts receive `skipped` reports and are valued from their last successful report (stale) or as `missing`.
- Authentication and authorization errors set the Connection `invalid`, are not retried, and stop scheduling that Identity until the User validates or enables it again. Rate-limit and temporary errors are retried twice within the cycle (after 2 s and 5 s); on exhaustion the Identity's Accounts are `failed` for this cycle.
- An Account Type the Platform reports as not enabled yields a `failed` report with the Platform reason; sibling Accounts are unaffected.
- The Valuation Point is always written, even if every Identity failed, so history reflects process uptime rather than Platform uptime.
- A runner error (database failure, cancelled context) retries the job with exponential backoff and jitter up to three attempts, then marks it `failed`; the next scheduler tick creates a fresh cycle.

## 10. Development workflow and deterministic data

```text
plutus [--config FILE] [--env-file FILE] serve
plutus [--config FILE] [--env-file FILE] migrate status | migrate up
plutus [--config FILE] [--env-file FILE] user create | user disable | user reset-password
plutus [--config FILE] [--env-file FILE] db seed --profile minimal|edge-cases|walkthrough
plutus [--config FILE] [--env-file FILE] db reset --profile minimal|edge-cases|walkthrough
plutus [--config FILE] [--env-file FILE] collect --portfolio <uuid>    # run one cycle now and wait for it
```

Seeds are generated in Go (`db/seeds`) from the same deterministic `fake` scenario the Adapter uses at runtime, so a lane that keeps collecting continues the seeded series without a jump. A profile inserts configuration, prices, cycle jobs, and Account Reports only; `db seed` and `db reset` then seal each live Identity's scenario credentials, enable it through the configured Adapter (with `fake_adapter = true` and a master key; otherwise the Identities stay `unconfigured`), and run `valuation.Rebuild` so every Valuation Point is written by the real code.

| Profile | Content |
| --- | --- |
| `minimal` | alice's Binance Identity with two selected Accounts, three hours of 15-minute cycles, one USDT flow; bob unconfigured |
| `edge-cases` | seven local days of two-hour cycles: a manually mapped `WBTC`, an unpriced `TOKENX`, a full day without points, a deselected and a newly selected Account (Boundary Events), an OKX key that turns invalid (stale), a Bybit Account that never succeeds (missing), a BTC flow valued from prices, and a `TOKENX` flow that cannot be valued |
| `walkthrough` | forty days of two-hour cycles across Binance, OKX, and Bybit, one rate-limited Bybit day, an archived Identity, USDT/BTC/USDC/ETH flows, plus bob's three-day series |

`db reset` drops every table, migrates, and seeds; it requires `[database].allow_reset = true` and a database named `plutus` or `plutus_<suffix>` without `prod`. The integration test in `db/seeds` applies every profile to a scratch database and asserts the §13 rules on `edge-cases`. Lanes and scripts are described in the README.

## 11. Observability and operations

`log/slog` structured logs with request and job IDs; no secrets, payloads, or audit documents in logs. Graceful shutdown stops new claims and lets the current cycle finish or lease-expire. High-signal events: Valuation Point written with issues, Connection set `invalid`, scheduler or pruning failure, migration mismatch at readiness.

## 13. Acceptance matrix

Coverage labels: **test** (automated in `go test`), **seed** (asserted by the `edge-cases` integration test), **lane** (exercised on the Agent lane against the fake Adapter), **Phase 5** (needs a live Adapter).

### 13.1 Ownership (test)

User A gets 404 on User B's resources; composite FKs prevent cross-Portfolio links; the birth Portfolio is undeletable; additional Portfolios cascade-delete.

### 13.2 Collection and valuation

- A cycle with all Connections succeeding writes one point whose total equals the sum of Account values (seed).
- A cycle where one Account fails writes a point using that Account's previous report, marked `stale` with the earlier `reportObservedAt`; the total does not drop (seed).
- A successful report that omits a previously held coin removes that coin from the current holdings and the point's value (lane).
- An Account with no successful report ever produces `method = missing`, `valueUsd = null`, and an `incomplete` point whose total is still the sum of the others (seed).
- A Balance with no price is listed with `noPrice`, excluded from the value, named in `omitted`, and makes the Account and point `incomplete` (seed).
- USDT and USDC Balances value at exactly 1 USD without a price row (test).
- An Account with `equity` reported is valued by it even when its Balances would sum differently (seed).

### 13.3 Boundary, flows, and periods

- Selecting a funded Account mid-series produces a Boundary Event contribution equal to its first value; deselecting produces a withdrawal equal to its last value; the Value Change spanning them subtracts both (seed).
- A manual BTC Capital Flow converts at the nearest Platform price at its effective time; a flow with no price within 24 hours leaves the spanning Value Change `incomplete` and names the flow (seed).
- Period Close picks the last point before each local boundary; a day without points has no Period Close, and the week containing it is `incomplete` (seed).
- Changing the Portfolio timezone changes Period Close selection without any write (lane).

### 13.4 Connections and Adapters

- Enabling a Connection without a successful validation is refused with 422 (lane).
- An authentication error during a cycle sets `invalid`, records the reason, and the next scheduler tick skips that Identity (lane, Phase 5).
- A rate-limit error is retried with backoff and does not set `invalid` (test on the fake, Phase 5 live).
- A selected Account Type the Platform reports as not enabled yields a `failed` report with the Platform reason; sibling Accounts succeed (Phase 5).
- No row, log, job detail, or response contains a raw Platform payload or credential material (review, Phase 5).

### 13.5 Catalog

- A new symbol on a second Platform maps to the existing Asset automatically (test).
- A manual mapping override recalculates the points of every Portfolio holding that listing and stamps `recalculated_at` (seed, lane).

### 13.6 HTTP, security, frontend (test, lane)

Decimal round-trip, ETag 412, idempotency 409, pagination stability, Problem Details with `traceId`, TLS matrix, theme and accessibility checks remain as before.
