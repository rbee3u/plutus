# Separate recorded interface evidence from synthetic tests

Using each response both to prove an exchange's current contract and to supply test business values made new captures change unrelated assertions and forced account preparation to follow test scenes. Replace ADR 0036's combined sample library with two independent flat directories per Platform: `evidence/` contains owner-reviewed recorded responses; `testdata/` contains independently constructed synthetic responses based on official documentation and available evidence. Tests cannot load recordings, files need not correspond one-to-one, and new evidence does not regenerate mocks. This trades automatic replay of every capture for stable deliberate mapping tests and explicit review of document/response differences; ADR 0027's distinction between documented support and observed real coverage remains.

Both layers use source/request/body, HTTP status, recorded-only actual UTC recordedAt, optional notes and text bodyFormat. Documentation URLs, preparation settings, observed differences and missing evidence live in Platform inventories, not a third file source or dependency manifest. Recorded bodies are never spliced or given synthetic business values. Market lists retain prepared instruments and representative product/settlement/contract-unit shapes; known balance/position lists omit only redundant all-zero rows, preserving representative shapes/settings and all debt, interest, margin, unknown fields, nulls and empty strings. Whole retained rows and original aggregate/count fields stay unchanged; notes explain trimming and identity/secret redaction.

Keep one explicit allowlisted request per `adapter record`, with native signing and no extra reads, pagination, retries, redirects or refusal probes; Kraken WS permits only its required challenge/subscription/snapshot. Local keep-symbol hints do not affect the request. An owner-approved preparation round may execute an explicit sequential list of commands and stops on the first request/write failure; successful files are not rerecorded. Each command writes one sanitized JSON atomically without overwrites under gitignored tmp/evidence. Unsafe redaction writes nothing; safe failures and empty responses remain in tmp by default. Format/safety/critical-shape review and owner review precede evidence promotion, independently of full Adapter replay. Parsing fixes get their own synthetic regression tests. Freeze accepted evidence and record replacement reasons; unavailable critical real states stay named gaps while other interfaces proceed.

Remove the previous recordings and their tmp capture/replay scratch directories. Initialize all four Platforms' synthetic tests from official response contracts, retaining meaningful nonempty, mode, pagination, failure, storage and valuation assertions. Start new evidence acquisition in Binance → OKX → Bybit → Kraken order, combining coexisting products/positions and changing settings only for critical request or response differences. Do not expand supported structures, margin modes or products. Ordinary tests remain network-guarded, strict on unknown requests and unused expected response steps; make test-live stays removed. Runtime serve/worker/collect behavior, fake Adapter and temporary MySQL rules are unchanged. Code deliveries pass ordered format/build/test/lint and dist; the agent lane is required only when runtime/API/UI behavior changes.
