# Use flat interface samples and single-request recording

Historical decision. [ADR 0037](./0037-separate-recorded-evidence-from-synthetic-tests.md) separates recorded evidence from synthetic test inputs and replaces the provenance, trimming and promotion rules below. Single-request networking restrictions remain.

Scenario manifests mixed response provenance with account applicability, duplicated common interfaces and made a small recording request consume unrelated endpoints. Replace ADRs 0034 and 0035 with one flat `testdata/` sample library per Platform and one explicit request per recording. This also replaces ADR 0023's historical online smoke and delivery gates; its fake Adapter and temporary-database rules remain. Keep ADR 0027's distinction between documented support and real evidence.

A file contains one response, named after its interface with an optional semantic variant for necessary request or mapping differences. Go tests explicitly select files and dispatch by service, method, path and exact business query/form values. Repeated requests and pagination use explicit response sequences; missing files, unexpected requests and unconsumed expected steps fail. There are no manifests, category directories or implicit PM/Unified fallbacks. Samples may be combined across dates to verify mapping; they do not prove a coherent real asset total or an atomic Platform snapshot.

Use top-level `source`, `request`, `body`, HTTP `status`, and provenance-specific `recordedAt` or official `documentation`. Optional `notes` explain necessary sanitation, market trimming or document construction; non-JSON text adds `bodyFormat: "text"`. Parameters use a string for one value and string arrays for multiple values, preserving pagination and cursors without a second decode. Authentication fields are excluded. Drop duplicate Platform, scope, scenario, batch, phase and occurrence metadata. Document-derived illustrative values remain documented evidence; intentionally altered real business values are synthetic.

`plutus adapter record --platform <platform> --only <interface> [--variant <name>]` validates parameters before reading keys or networking, uses native routing and signing, and sends exactly one HTTP request without configuration, time, price, product, aggregate, retry, redirect, additional page or refusal probes. Kraken WS captures one logical snapshot through its required challenge/subscription, without REST. Remove full capture and batch verification. List/dry-run are offline. Save one sanitized response atomically without overwrites in a new gitignored `tmp/` directory; unsafe evidence is never written. Platform/HTTP or writing failures return nonzero, even when safe failure evidence is retained. Saving is not mapping acceptance and never promotes a sample; empty responses stay in `tmp/` by default.

Delete all prior committed recordings without relabeling or migrating them. Rebuild documented response contracts from official sources, preserve meaningful mapping and failure assertions, and leave historical `tmp/` captures untouched. The resulting library has zero recordings under this standard. Acquire new owner-prepared evidence per interface in Binance → OKX → Bybit → Kraken order. Review and offline tests precede promotion; freeze accepted samples and document targeted replacement reasons. Ordinary tests block exchange networking even when an Adapter swallows the error into a failed report. Runtime `serve`, worker and `collect` retain real read-only collection. Validate each code delivery with ordered format/build/test/lint gates and `make dist`; exercise the agent lane only when runtime/API/UI scope requires it.
